The pitch for every subscription ebook service is that your books are convenient — for them. Kokoro Ebook Reader takes the opposite side: your PDFs and EPUBs sit on your own hardware, and the text-to-speech runs there too. It is a local, self-hosted reader that reads books aloud with word-level synchronized narration, built the way I wish every reading app worked.

<h2 id="the-reader">The reader</h2>

The reading surface handles the two formats that matter — PDF and EPUB — through different doors: PDF.js renders the original layout with a sentence overlay drawn over the actual page, while EPUB text reflows with bionic-reading weighting (fixation and bold-ratio are user settings, not a gimmick toggle). Around the page sit the boring-but-real parts of a reading product: bookmarks, folders, a library grid, full-text search, themes, reading progress, and an MP3 export for taking a chapter to the car.

The thing that makes it a talking reader rather than a PDF with an audio file stapled to it is the sync manifest. Word-level timings — and PDF bounding boxes — flow from the alignment stage to the frontend, so the highlight tracks the voice, the sentence highlights on the rendered page, and locking the screen on an iPad keeps the chapter playing through Media Session controls.

<h2 id="the-pipeline">The narration pipeline</h2>

Reading a chapter aloud should feel instant in the player, so nothing synthesizes live during playback. Each document goes through an immutable render pipeline: extract the text, synthesize it once, force-align the audio to the text, then encode the result as Ogg Opus at four speed tiers — 1.5×, 2.0×, 2.5×, and 3.0× — plus WebM copies for streaming. The player receives a gzip-verified sync manifest and fetches chunks; switching speed is a different artifact, not a pitch-shifted stutter.

The synthesis itself is Kokoro-82M, and how it runs is a runtime decision, not an architecture decision: four engines are behind one manager and hot-swappable through the API — the torch pipeline on a local GPU, Kokoro-82M through ONNX Runtime for leaner CPU/GPU machines, Piper as a lightweight fallback, and a remote Modal GPU for machines with none. Same voices, same manifest, whichever engine you can afford to run.

<h2 id="offline">Offline and installation</h2>

The frontend is an installable PWA: a service worker, OPFS storage for downloaded documents, an offline progress queue, and Add-to-Home-Screen on desktop and iPad (streamed as WebM/Opus over HTTPS — the tailnet deployment path is documented in the repo). For people who prefer a binary, the same app ships three ways: a Docker Compose stack built on NVIDIA CUDA images, a Flatpak manifest, and a Debian package.

Scale, honestly stated: this is the largest single-owner codebase linked from this site — 27 Svelte components on the frontend, roughly 13,500 lines of TS/Svelte against about 18,000 lines of Python, and 135+ test files across frontend unit tests, Playwright end-to-end specs, and backend pytest. It is not a demo with a landing page; it is an application with a test suite.

The 8-bit intro music on this site, incidentally, is the same spirit: local playback of things you control. Kokoro Ebook Reader is open source — the repository is the ledger for everything claimed above.
